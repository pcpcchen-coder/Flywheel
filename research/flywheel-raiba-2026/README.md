## 建議立項決策

**有條件通過 12 個月 MVP，不建議直接核准 MW 級全功能系統。**

建議主計畫名稱：

> **飛輪功率掩護下之 RAIBA 可重構電池系統：重構暫態穩定、故障功率橋接與診斷驅動重構技術**

核心定位不是再做一次傳統功率分流，而是：

- **飛輪負責時間域**：高頻功率、重構暫態補償、故障橋接與診斷功率掩護。
- **RAIBA 負責空間域**：模組串併聯、旁路、輪替、故障隔離與健康度管理。
- **兩者共同形成閉環**：EIS／SOH 結果即時改變模組功率限制、重構時機與拓撲選擇。

### 架構分工

| 架構 | 內容 | 立項角色 |
|---|---|---|
| A | AC 耦合或固定 DC-link，雙方各有變流器 | 12 個月 MVP 與保底路線 |
| B | 共 DC-link＋選擇性雙向 DC/DC＋RAIBA | 主研究架構 |
| B2 | RAIBA 離散電壓追蹤可變 DC-link，嘗試減少主功率級 | 高風險、可停止子題，不列必成 |
| C | MMC、多埠、TAB／MAB | MW、中壓與長期路線 |

## 查新結論與不可過度宣稱事項

本研究已納入直接前案，**不得再使用以下宣稱**：

1. 「全球首次結合飛輪與可重構電池」——2026 年 Paizulamu 等已在調度模型中納入 FESS＋DRBN。
2. 「首次利用可重構電池在無額外電源下執行 EIS」——Kersten 2020、Chen 2024、Peng 2026 已有直接前案。
3. 「共 DC-link＋飛輪＋電池就是新架構」——Hu、Liaw 2013 已有實測。
4. 「功率分配、SOC 自恢復、容量最佳化就是核心創新」——相關研究與工程已相當成熟。

可防守的研究缺口是：**RAIBA 開關級重構暫態、飛輪即時故障功率橋接、服務不間斷高品質 EIS，以及診斷結果即時回授拓撲選擇的完整實驗閉環。** 此表述仍須在正式申請前補做專利檢索與 FTO。

## 建議 KPI 與停止條件

**以下全部是立項建議，不是現有成果；應在 M0–M2 依設備、場域與安全規範正式凍結。**

| 面向 | 建議目標 |
|---|---|
| 重構暫態 | 湧流＜2 pu 且＜1 ms；DC-link 缺口＜5%、＜10 ms |
| 對外服務 | PCS 側功率擾動＜2%；單模組失效輸出跌落＜5% |
| 高頻電流 | 電池＞0.1 Hz 分量相對無飛輪基線衰減≥20 dB |
| EIS | 中頻幅值誤差＜5%、低頻＜10%；量測＜60 s |
| 即時控制／HIL | EMS 單步＜10 ms；HIL 暫態誤差＜10%；故障案例≥50 |
| 效率 | 架構 B 全工況淨效率增益目標≥1.5% |

主要 Kill criteria：

- B2 緩衝／預充成本超過省下 DC/DC 成本的 50%，停止 B2。
- 實測雜訊下 EIS 中頻誤差仍＞10%，停止高頻在線 EIS。
- 飛輪×重構交互綜效＜3%且對模型誤差穩健，停止複雜協同／延壽宣稱。
- LCOS＞傳統 HESS 的 1.05 倍且無應用可翻正，停止商業化線。
- 暫態與 EIS 兩個 Gate 同時失敗，退守「架構 A＋RAIBA 診斷與健康管理」，不放大功率。

| 對照 | 電池架構 | 飛輪 |

## 從來源重新產生

- Node.js 18 以上、`docx` 9.7.1。
- Python 3、Pillow、PyYAML。
- 技術圖生成器預設使用 Linux Noto Sans CJK 字體；其他系統請修改 `source/make_figures.py` 的字體路徑。
- 若要執行簡報結構檢查與截圖，另需 `kimi-slides` CLI。

```bash
cd research/flywheel-raiba-2026/source

node create_report.js ../report/飛輪儲能_RAIBA_技術研發立項完整報告.docx
python3 build_pptd.py

```

生成器均使用相對路徑；`source/assets/`、`slides/pages/` 與 `slides/media/` 必須一起保留。
