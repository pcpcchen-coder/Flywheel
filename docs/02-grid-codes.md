# 02 · 電網規範：ramp、動態範圍與 LVRT

規範有兩端，而且方向相反：**平常要慢**（ramp 限值），**故障後要快**（LVRT 恢復要求）。這個衝突是 v2 提案的核心。

## 2.1 ramp 與動態範圍：數字各家不同

| 來源 | 規定項目 | 數值／做法 |
|---|---|---|
| 論文（Microsoft、OpenAI、NVIDIA，arXiv 2508.14318） | ramp-up／down（MW/s）、動態範圍、頻域限制 | 例：100 MW 作業動態範圍 10 MW；0.1–20 Hz 能量 ≤ 20%；排程 5–15 分鐘比對 |
| Southern Company | 正常運轉最大有功 ramp | **20 MW/min**（≈ 0.33 MW/s；唯一公開的明確數值） |
| AEP | Load Ramp Schedule | 步階大小與節奏，依閃變／RVC 規劃限值檢核 |
| Dominion | POI 瞬時電壓波動 | ≤ 3%；永久 PQ 計量（諧波至 50 次、Pst／Plt） |
| ERCOT | Load Commissioning Plan、SSO 研究 | 尚無明確 ramp 數值 |
| 台電 | 大型 AI 負載併網審查 | **待確認** |

**設計策略**：ramp 限值做成可設定參數（0.3–10 MW/s），能量規格依最嚴格的目標市場決定（見 [05 容量估算](./05-sizing.md)）。

## 2.2 LVRT：ERCOT NOGRR282

ERCOT NOGRR282 是目前最完整的大型計算負載穿越規格。這是**負載**規範，不是發電機 LVRT，但精神一樣。

| 電壓（pu） | 最短穿越時間 |
|---|---|
| 1.10–1.20 | 2.0 s |
| 0.90–1.10 | 連續運轉 |
| 0.80–0.90 | 2.0 s |
| 0.50–0.80 | 0.5 s |
| 0.20–0.50 | 0.25 s |
| < 0.20 | 0.15 s |

其他要求：

- **恢復**：電壓回到 0.9 pu 以上後，**1 秒內**恢復至故障前用電的 **90%**。
- **電流上限**：電壓異常期間電流不超過正常最大值的 **125%**（修訂中）。
- **不得因驟降次數轉供**：禁止僅因短時間多次驟降就切到備援（直接回應 2024 北維吉尼亞事件）。
- **頻率穿越**：有功維持 ±10%；58.8–61.2 Hz 連續；57.0–58.8 與 61.2–61.8 Hz 至少 299 s。
- **狀態**：2026/6 ERCOT 董事會通過、待 PUCT 核定；2025/11/14 前取得核准者適用既有規定；2028 後新案深度驟降要求更嚴。

## 2.3 衝突點：平常要慢，故障後要快

| 情境 | 要求 | 等效變化率 |
|---|---|---|
| 平常（作業啟停、checkpoint） | dP/dt ≤ R | R ≈ 2 MW/s，最嚴 20 MW/min（0.33 MW/s） |
| 故障清除後（LVRT 恢復） | ≥ 90%／1 s，且電流 ≤ 1.25 pu | 70–90 MW/s |

負載本身做不到兩全：

- **UPS walk-in**：夠慢，但違反 1 秒恢復（示意模擬 3.0 s）。
- **瞬間回接**：夠快，但違反 ramp 與電流上限。
- **GPU 功率地板**：壓得住 ramp，救不了電壓驟降，還要空轉燒電。

→ 需要在 PCC 上放一個**雙向、毫秒級、有足夠能量的可控電流源**：飛輪 PCS。故障恢復窗內的 ramp 通常視為豁免，但仍受 125% 電流上限約束（NOGRR282 草案）。
